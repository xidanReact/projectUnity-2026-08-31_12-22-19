# Оболочка приложения и кампания на карте

> Дата: 2026-09-01 · Статус: согласовано, готово к написанию плана
> Заменяет: экран выбора патогена и бесконечный цикл уровней из Фазы 2

## Зачем

Сейчас игра запускается сразу в экран выбора патогена, а забег — бесконечный цикл
уровней, который кончается только смертью. Победы не существует. Нужен нормальный
мета-слой мобильной игры: загрузочный экран, главный экран с персонажем, настройки,
четыре раздела и кампания в виде карты с поузловым прохождением.

## Что входит и что нет

**Входит:** каркас оболочки (сплэш, шапка, таб-бар, главный экран, модалка настроек),
кампания на карте с брифингом узла, звёздами и наградами, перенос существующего
магазина улучшений, разрезание `GameHud`, схема сейва версии 2 с миграцией.

**Не входит:** одежда и режим «Битва» — только заглушки «в разработке». Усиление
босса. Биомы 2 и 3 играбельными не становятся — врагов для них не существует,
рескином биома 1 они не подделываются. Сохранение билда при убийстве приложения
посреди биома.

## Ключевое решение: билд живёт весь биом

Апгрейды и мутации копятся через все узлы биома и сгорают при смерти или выходе
из биома. Босс — проверка собранного билда, а не отдельный ни с чем не связанный
уровень. Это сохраняет смысл пула из 25 апгрейдов и 11 мутаций: за один узел
игрок берёт 1-2 из них, за биом — шесть-восемь.

Прямое следствие, которое надо заложить сразу: **апгрейд выдаётся только за первое
прохождение узла в текущей попытке биома.** Без этого игрок фармит первый узел,
собирает полный билд и заходит к боссу неубиваемым.

## Архитектура

Три слоя, которые сейчас слиты в `GameState` и `GameHud`:

### AppFlow

Машина состояний приложения: `Splash → Home → (Upgrades | Wardrobe | Campaign | Battle)
→ Briefing → Combat → LevelResult → Campaign`. Не знает ни про врагов, ни про пулы.
Владеет `ScreenStack` и текущим `BiomeRun`.

### GameRunner

Ужимается до боя одного узла. Уходит: `levelsInBiome`, зацикливание
(`LevelNumber % _levels.Count`), `RestartToSelect`, поле `FirstBossLevelIndex` и
отладочный вход «сразу к боссу» (карта делает это честно).

Появляется: `StartNode(CampaignNode node, BiomeRun run)`, замер времени уровня,
исход `NodeOutcome { Cleared, Failed, ElapsedSeconds, Kills }` и событие
`NodeFinished`. Апгрейды `GameRunner` больше не роллит сам — этим управляет
`AppFlow`, потому что решение «давать ли апгрейд» зависит от состояния попытки биома.

### BiomeRun

Активная попытка биома, живёт в памяти:

```
biomeId, PathogenData, PlayerStats, состояние UpgradeSystem,
nodesRewardedThisAttempt: HashSet<string>
```

Создаётся при входе в первый узел биома, уничтожается при смерти или выходе из
биома. Выход из биома с живым `BiomeRun` спрашивает подтверждение.

Патоген фиксируется в момент создания `BiomeRun` — тем, что выбран на главном
экране. Смена патогена в карусели при живом `BiomeRun` спрашивает то же
подтверждение, что и выход из биома: билд привязан к патогену и пересадке
не подлежит.

## Навигация

`ScreenStack` — стек экранов плюс отдельный слой модалок поверх. Базовый класс
`UiScreen` с `Build(parent) / OnShow() / OnHide() / Tick()`.

Тикается **только активный экран**. Сейчас `GameHud.Update` каждый кадр обходит
все пять экранов и обновляет невидимые.

Оболочка: шапка (золото, биомасса, шестерёнка слева) + область контента + таб-бар.
Таб-бар виден на главном экране и на всех четырёх страницах, чтобы переключаться
напрямую; кнопка «домой» в шапке возвращает к персонажу. В бою оболочка скрыта
целиком.

## Данные кампании

`CampaignNode`:

```
id            стабильная строка: "b1_n3", "b1_boss" — уходит в сейв, менять нельзя
level         LevelData
mapPosition   Vector2 в координатах карты
baseGold      база награды
baseBiomass   база награды
```

`BiomeData`: `id, displayName, accentColor, nodes[], unlocked`.
`CampaignMapData`: три биома, первый — настоящий.

Биом 1 «Кровоток»: 8 узлов — 7 боевых (чередование волн и сегментов, как в текущем
`CampaignGenerator`) плюс Лимфоузел. Биомы 2 и 3 присутствуют в данных и рисуются
на карте заблокированными с подписью «в разработке».

**Открытие узлов:** узел доступен, если предыдущий пройден хотя бы на одну звезду.
Первый узел биома доступен всегда, если биом открыт.
**Открытие биома:** биом N+1 открывается, когда босс биома N пройден.

## Звёзды

Ручных порогов на уровень нет — порог считается из содержимого самого уровня:

```
парТайм = Σ по волнам ( TotalCount × среднее(spawnIntervalRange) + postWaveDelay )
```

Это физический минимум: быстрее уровень пройти нельзя, враги просто не успеют
появиться. Формула сама подстраивается под любой состав уровня.

| Звёзды | Условие |
|---|---|
| ★ | уровень пройден |
| ★★ | время ≤ парТайм × 1.7 |
| ★★★ | время ≤ парТайм × 1.15 |

Три звезды читаются как «убивал не медленнее, чем они появлялись».

Для босс-уровня волн нет, поэтому парТайм — новое поле `BossData.parTimeSeconds`,
стартовое значение 70. Множители те же.

## Награды

База на узел (до множителя жадности):

```
baseGold    = 20 + 6 × индекс узла в биоме
baseBiomass = 15 + 5 × индекс узла в биоме
босс: обе базы × 3
```

Множитель за звёзды: 1★ = 1.00, 2★ = 1.25, 3★ = 1.50.

Выплата:

| Случай | Сколько |
|---|---|
| Первое прохождение | полная награда за полученные звёзды |
| Улучшил звёзды | разница между новым и старым тиром |
| Повтор без улучшения | 30% от награды за текущий тир |
| Смерть | ноль, звёзды не меняются, `BiomeRun` сгорает |

Существующий `MetaProgression.GreedMultiplier = 0.65` применяется к обеим валютам
в момент начисления — это остаётся единственной точкой калибровки жадности.

## Валюты

Золото — валюта косметики (раздел «Одежда»). Биомасса остаётся валютой перманентных
улучшений. Обе капают с узлов кампании.

## Сейв

`PlayerProgress` переходит на версию 2:

```
version = 2
biomass, gold
perks[]                        без изменений
settings { master, music, sfx, playerName }
lastPathogen                   что показывать на главном экране
campaign {
  nodes[] { id, stars }
  biomesUnlocked[]
}
totalRuns, bestLevelReached, totalKills, bossesDefeated
```

`bestLevelReached` теряет смысл вместе с бесконечным забегом: «дальше всех
пройденный уровень» больше не определено. Поле сохраняется ради миграции, но
перестаёт обновляться; прогресс по кампании теперь читается из `campaign.nodes`.
`totalRuns` начинает считать попытки биома, а не забеги.

`ProgressMigration` переносит v1 в v2: перки и биомасса как есть, золото в ноль,
кампания пустая, настройки по умолчанию (громкость 1.0, имя пустое). Миграция —
единственное место, где можно молча потерять чужой прогресс, поэтому покрывается
тестами отдельно от всего остального.

Запись остаётся атомарной через временный файл, как в `JsonProgressStore` сейчас.
Сохранение — по событию (конец узла, покупка, смена настроек), не по таймеру.

## Настройки и звук

Модалка поверх текущего экрана, не отдельный экран. Три слайдера громкости
(общая, музыка, эффекты) и поле ввода имени игрока.

Звуков в проекте нет — по dev-plan.md это Фаза 2.5.

`AudioMixer` здесь не подходит: это ассет проекта, его нельзя создать в рантайме,
а вся сцена у нас собирается кодом. Поэтому `AudioService` — обычный синглтон,
который держит три значения, пишет общую громкость в `AudioListener.volume` и
отдаёт `MusicVolume` / `SfxVolume` наружу как множители. В Фазе 2.5, когда
появятся настоящие звуки и ассет микшера, `AudioService` меняет реализацию
внутри, а вызывающая сторона — нет.

## Сплэш

Полноэкранная заставка: слот под будущую картинку (пока заливка плюс название),
полоса прогресса, отражающая реальные шаги инициализации, и минимальное время
показа 1.2 секунды, чтобы экран не мигал на быстрых устройствах.

## Поток экранов

```
Запуск → Сплэш → Главный (персонаж + таб-бар)
  Улучшения → магазин перков (перенос как есть)
  Одежда    → заглушка
  Битва     → заглушка
  Кампания  → карта → тап по узлу → брифинг → бой
                 бой выигран  → результат (звёзды + награда + 1 из 3 апгрейдов) → карта
                 бой проигран → результат (провал) → карта, BiomeRun сгорел
                 босс побеждён → разблокировка следующего биома → карта
```

## Производительность

- `CombatHud` сейчас каждый кадр собирает три интерполированные строки — около
  трёх аллокаций на кадр в бою. Переезжает на `StringBuilder` с обновлением только
  при смене значения.
- Экраны строятся один раз и выключаются; тикается только активный.
- Узлы карты — переиспользуемые `MapNodeView`, а не пересборка иерархии при каждом
  входе на карту.
- Пулы врагов, `Battlefield` и поиск целей не трогаются.

## Тесты

Добавляются к существующим 64 EditMode-тестам:

| Что | Почему именно это |
|---|---|
| Расчёт парТайма | от него зависят все звёзды разом |
| Пороги звёзд на границах | классическое место off-by-one |
| Выплата: первое / улучшение / повтор | здесь ломается экономика, причём молча |
| Миграция v1 → v2 | единственное место безвозвратной потери прогресса |
| Открытие узлов и биомов | ошибка либо запирает игрока, либо открывает всё |
| Апгрейд не выдаётся за повтор узла в попытке | закрывает фарм-эксплойт билда |

## Известные ограничения

`BiomeRun` живёт только в памяти. Если ОС убьёт приложение посреди биома, билд
пропадёт, а пройденные узлы останутся. На мобильных это заметно; чинится
отдельной задачей — сериализацией `PlayerStats` и состояния `UpgradeSystem`.
