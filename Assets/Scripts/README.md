# Фаза 1 — прототип core loop

Играбельный прототип lane-defense по dev-plan.md. Арт плейсхолдерный (спрайты
рисуются кодом), звука нет — оба пункта по плану идут после MVP.

## Как запустить

Открыть проект в Unity 6000.5.10f1, открыть `Assets/Scenes/SampleScene.unity`,
нажать **Play**. Больше ничего настраивать не нужно: `GameBootstrap` через
`[RuntimeInitializeOnLoadMethod]` сам собирает камеру, арену, пулы, спавнер и HUD.

Управление: тянуть палец (или ЛКМ) влево-вправо; в редакторе — `A`/`D` или стрелки.
Атака автоматическая, по ближайшей цели в радиусе.

## Что реализовано

| Пункт плана Фазы 1 | Где |
|---|---|
| 4 патогена с уникальными пассивками | `Player/Abilities/` |
| Движение только влево-вправо по полосе | `Player/PlayerController.cs` |
| Авто-атака в направлении угрозы | `Player/PlayerWeapon.cs` |
| Волны и сегменты (смешанный тип уровней) | `Enemies/EnemySpawner.cs`, `Data/LevelData.cs` |
| Враги Биома 1 (нейтрофил, макрофаг, антитело) | `Data/EnemyCatalog.cs`, `Enemies/Enemy.cs` |
| Object pooling с самого начала | `Core/ObjectPool.cs`, `Core/PoolHub.cs` |
| Таймер эскалации сложности | `Core/DifficultyDirector.cs` |
| Выбор 1 из 3 апгрейдов после уровня | `Upgrades/` |
| Частичная рандомизация уровня | `Data/CampaignGenerator.cs` + шаффл в спавнере |

Босса Биома 1 (Лимфоузел) в Фазе 1 нет — по плану он относится к Фазе 2.

## Что сознательно временное

- **HUD на IMGUI** (`UI/PrototypeHud.cs`) — чтобы не собирать uGUI-иерархию до
  валидации механик. Заменяется в Фазе 2 вместе с экраном смерти и магазином.
- **Плейсхолдер-спрайты** (`Core/PlaceholderArt.cs`) — генерируются в рантайме,
  выбрасываются в Фазе 2.5.
- **Сборка сцены кодом** (`Core/GameBootstrap.cs`) — в Фазе 2 становится
  нормальной сценой с сериализованными ссылками.
- **Баланс в коде** (`Data/EnemyCatalog.cs`, `PathogenData.CreateDefault`) —
  меню `Pathogen → Создать балансовые ассеты (Фаза 1)` выгружает эти значения
  в `Assets/GameData/*.asset`, после чего крутить их можно без пересборки.

## Поиск целей

Все запросы «кто ближайший / кто в радиусе» идут через `Core/Battlefield.cs`.
Сейчас это линейный перебор — на прототипных объёмах его достаточно. Когда
профайлер Фазы 5 упрётся в это, меняется только внутренность `Battlefield`.

## Критерий готовности фазы

> Все 4 патогена ощущаются по-разному, и прототип цепляет на 10+ минут повторных забегов.

Проверяется вручную: по забегу за каждый патоген, с вниманием к тому, меняет ли
пассивка способ игры, а не только цифры.

# Фаза 2 — вертикальный срез (в работе)

## Сделано: босс Биома 1 «Лимфоузел»

`Bosses/` + `Data/BossData.cs`, `Data/BossCatalog.cs`.

Босс-уровень — вариация core loop, а не новая система: патоген по-прежнему ходит
влево-вправо и бьёт автоматически, меняется только цель. Босс въезжает сверху,
встаёт на боевую позицию и остаётся неподвижным.

Четыре сегмента, у каждого своё здоровье и своя атака. Сегмент — это и есть фаза:
она работает, пока сегмент цел, поэтому порядок «разбора» босса выбирает игрок.

| Сегмент | Атака |
|---|---|
| Афферентный сосуд | призывает нейтрофилов |
| Фолликул | веер снарядов вниз |
| Синус | телеграфированный удар по участку полосы |
| Эфферентный сосуд | призывает антитела |

За каждый снятый сегмент оставшиеся ускоряются (`rageIntervalScalePerKill`).

**Как протестировать:** на экране выбора патогена включить тумблер
«Сразу к боссу (отладка)» — забег начнётся сразу с босс-уровня.

**Важное ограничение позиции:** `BossData.battleOffsetFromLane` должен быть меньше
самой короткой дальности атаки патогена (сейчас 6.5 у бактерии), иначе до сегментов
физически не дотянуться и уровень подвиснет.

## Рефакторинг под это

Введён `Core/ICombatTarget.cs`. До Фазы 2 единственной целью в бою был `Enemy`,
но сегменты босса не враги и не живут в пуле. Теперь снаряды, споры, авто-атака и
поиск целей работают с интерфейсом; `Battlefield.HostileCount` стал `ThreatCount`
(сегменты босса не считаются угрозой — конец босс-уровня определяет сам босс).

## Сделано: система мутаций

`Player/PlayerMutations.cs` + пул в `Upgrades/UpgradeSystem.cs`.

Апгрейд правит цифры, мутация меняет поведение. В выборе из трёх мутация
занимает не больше одного слота (с второго уровня, шанс 45%), берётся один раз
и подсвечена в UI отдельно: выбор «мутация против цифр» читается, выбор из трёх
мутаций — уже нет.

| Патоген | Мутации |
|---|---|
| Общие | Разрывной снаряд, Кровожадность, Адреналин |
| Вирус | Пандемия (цепное заражение), Вирулентный штамм |
| Бактерия | Шипастая плёнка |
| Грибок | Грибница (соседние споры усиливают друг друга), Взрывные споры |
| Паразит | Кровосос, Контратака |

Цепное заражение затухает само: шанс на звено вдвое меньше, и каждое следующее
звено слабее по здоровью — иначе волна никогда бы не кончалась.

Всё поведение мутаций собрано в `PlayerMutations` с пятью точками подключения
(попадание, убийство, полученный урон, сработавший щит, уход в невидимость) —
следующая мутация стоит ровно столько, сколько стоит её эффект.

## Сделано: метапрогрессия

`Meta/`. Мягкая валюта — «биомасса», начисляется в конце забега за убийства,
пройденные уровни и поверженных боссов.

Пять перманентных улучшений (по 5 уровней, цена растёт линейно): Плотное ядро,
Агрессивный штамм, Ускоренный метаболизм, Гибкая мембрана, Дальнобойность.
Все пять — чистая арифметика над стартовыми статами, без новых точек подключения в бою.

**Сохранение:** JSON в `Application.persistentDataPath/progress.json`. Путь печатается
в консоль при старте. Запись идёт через временный файл с заменой: если процесс убьют
посреди сохранения (на мобиле это норма), старый файл останется целым.
Повреждённый файл не роняет игру и не теряется молча — пишется в лог.

Всё ходит через `IProgressStore`. Единственное место, где выбирается реализация, —
`GameBootstrap`; в Фазе 4 туда подставляется клиент Go-бэкенда.

**Калибровка жадности:** `MetaProgression.GreedMultiplier` = 0.65 — тот самый срез дропа
на ≈треть из dev-plan.md (целевой уровень 6-7 из 10). Вынесен отдельной константой:
это первое, что будет крутиться по данным софт-лонча.

Витрина — кнопка «Улучшения» на экране выбора патогена. Там же кнопка
«Сбросить прогресс» — без неё невозможно проверить, как игра выглядит для человека,
запустившего её впервые, а именно это проверяет критерий готовности Фазы 2.

## Сделано: расширенный пул апгрейдов

25 апгрейдов вместо 18. Добавлены две новые механики, которые раньше отсутствовали:

- **Криты** — `CritChance` / `CritMultiplier`, роллятся один раз на выстрел, а не на
  каждый снаряд веера (иначе мультивыстрел неявно умножал бы ценность шанса крита).
  Критический снаряд светлее обычного.
- **Снижение урона** — `DamageReduction`, отдельный компонент `Player/DamageReduction.cs`
  в той же цепочке `IDamageInterceptor`, что щит бактерии и прятки паразита.
  Потолок 60%, иначе апгрейды сложились бы в полную неуязвимость.

## Сделано: интерфейс на uGUI

`UI/GameHud.cs` + `UI/UiFactory.cs`. IMGUI-заглушка Фазы 1 заменена настоящей
Canvas-иерархией: пять экранов (выбор патогена, магазин, бой, выбор апгрейда, смерть),
`CanvasScaler` под опорное разрешение 720×1280 с подгонкой по высоте.

Два решения, которые стоит знать:

- **Legacy `UnityEngine.UI.Text`, а не TextMeshPro.** TMP требует однократного импорта
  «TMP Essentials» в проект; без него весь текст рендерится пустым. Для плейсхолдерного
  UI это лишняя ловушка на ровном месте.
- **`InputSystemUIInputModule`, а не `StandaloneInputModule`.** В проекте включён только
  новый Input System (`activeInputHandler: 1`) — со старым модулем кнопки молча
  перестали бы нажиматься.

Иерархия строится кодом, но ровно та же, что получилась бы при сборке руками, —
её можно вытащить в префаб, не переписывая логику.

Аварийный откат: `GameBootstrap.useLegacyImguiHud` возвращает старый IMGUI-HUD.

## Сделано: автотесты и сборки

`Assets/Tests/EditMode/` — 64 EditMode-теста. Запуск: **Window → General → Test Runner**,
вкладка EditMode, кнопка Run All.

Что покрыто и почему именно это:

| Область | Чем плоха ошибка |
|---|---|
| `Health` + цепочка `IDamageInterceptor` | общий код игрока и врагов — ломает обе стороны боя |
| `ObjectPool` | не падает, а тихо течёт объектами или выдаёт один инстанс дважды |
| `MetaProgression` | трогает сохранённый прогресс, а не только текущий забег |
| `JsonProgressStore` | единственное место, где данные игрока теряются безвозвратно |
| `UpgradeSystem` | правила выдачи невидимы на стороне вызова, сломать их легко |
| Кампания, фракции, статы | мелочи, на которых стоит весь остальной бой |

Отдельно зафиксированы два условия зависания уровня, которые иначе легко нарушить
правкой баланса: боевая позиция босса и дистанция антитела обязаны быть **меньше**
самой короткой дальности атаки среди патогенов, иначе до цели не дотянуться.

Под тесты код разложен по сборкам: `Pathogen.Runtime`, `Pathogen.Editor`, `Pathogen.Tests`
(asmdef не может ссылаться на предопределённую `Assembly-CSharp`, поэтому без этого
тесты не увидели бы игровой код). Побочный выигрыш — компиляция стала инкрементальной.

Три правки ради тестируемости: `JsonProgressStore` принимает папку (тесты не должны
трогать настоящий сейв игрока), `UpgradeSystem` и `MetaProgression` строят свои пулы
по требованию, а не только в `Awake` — вне режима игры `Awake` может не вызваться.
